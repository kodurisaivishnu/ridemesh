## Problems and learnings

- At the start of the day the laptop was already using 11 GiB of swap with no containers running. Most of the RAM is Chrome and VS Code. Close tabs before starting the stack, or everything will be slow and the numbers will be wrong.
- Redpanda dev-container mode is set up for speed, not safety: it skips fsync, so a crash can lose messages the broker already acknowledged. It also creates topics automatically, so a typo in a topic name makes a new, empty topic instead of an error. Recorded in ADR-0001. Turn auto-create off before Phase 1 uses the event catalog.
- Postgres `max_connections` is 100, shared by all five service databases on the one server. This is the limit behind backend problem 9.
- Measure before trimming. `docker stats` showed one number (893 MiB); per-process memory inside the container (`/proc/*/status`, because the image has no `ps`) showed where it went. Without that, the guess would have been "Prometheus or Loki", and the real cause was Grafana's unused plugins.
- `docker stats` memory moves a lot (300–580 MiB for the same idle container) while the laptop swaps: the kernel moves pages out and back in. The cgroup's `memory.stat` splits it into process memory (`anon`, ~330 MiB) and file cache. Process memory is the number to compare.
- Telemetry SDKs batch. A short script that exits without `shutdown()` sends nothing, and no error says so.
- OTLP names change on the way in: counter `smoke_runs` → `smoke_runs_total` in Prometheus; `service.name` → `job` in Prometheus and `service_name` in Loki.
- Swap was 95%+ full with everything running. When RAM and swap are both full, the kernel's OOM killer picks a process to kill, and it may pick Chrome or VS Code. Run `make obs-down` when observability isn't needed.

## Decisions

- Observability: `grafana/otel-lgtm` in one container, started only on demand ([ADR-0002](../adr/0002-observability-stack.md)).
- Python services send telemetry as OTLP over HTTP (port 4318), not gRPC: the OpenTelemetry default, and no large `grpcio` package in every service.
- OpenTelemetry SDK and OTLP exporter are root dev dependencies for now. Each service will declare its own when it is created.
- Three frameworks, as in the plan: Django (Identity, Trips), FastAPI (Realtime, Location, Dispatch), Flask (Pricing, Payments). Framework code stays in `api/` and `adapters/` ([ADR-0003](../adr/0003-frameworks.md)).
