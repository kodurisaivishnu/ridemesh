### 1. Decide how a service is built and run (20 min)

These choices repeat in all seven services, so make them once, today. Record them in `docs/adr/0004-service-skeleton-and-gateway.md`.

- [ ] **Folder:** `services/hello-fastapi/`, its own `pyproject.toml`, a member of the uv workspace. Hello services are throwaway: the real services start in Phase 1, from what we learn here.
- [ ] **Layout:** the plan's four layers (`domain/`, `application/`, `adapters/`, `api/`) are overkill for "hello". Use only `api/`, but keep framework imports out of anything that could be shared.
- [ ] **Tracing, recommended: zero-code.** `opentelemetry-instrument` wraps the app, and environment variables configure it (`OTEL_SERVICE_NAME`, `OTEL_EXPORTER_OTLP_ENDPOINT`, …). The setup is the same for all three frameworks, which Day 5 needs. Alternative: set up the SDK in code, as in `otel_smoke.py`. More control, but three versions of the same code.
- [ ] **How it runs:** in a container from Compose, because Day 5 needs all three behind Traefik. While coding, run `uv run uvicorn --reload` on the laptop.
- [ ] **Traefik routes, recommended: file provider.** Routes go in a small YAML file in `platform/traefik/`. The Docker provider reads container labels instead, but needs `/var/run/docker.sock` mounted, and that socket gives full root control of the laptop even when mounted read-only.

### 3. Container image and Compose (40 min)

- [ ] `services/hello-fastapi/Dockerfile`, multi-stage. Stage 1: uv (`ghcr.io/astral-sh/uv:0.13.0`, same as the laptop) installs only this service's packages from the root `uv.lock` (`uv sync --frozen --no-dev --package hello-fastapi`). Stage 2: `python:3.13.16-slim-trixie` (same Python as `.venv`) with just the virtualenv and the code.
  - The build context is the repo root, because `uv.lock` lives there. Add a `.dockerignore` so `.venv`, `.git` and caches are not sent to Docker.
  - Run as a non-root user.
- [ ] Compose service `hello-fastapi` in a new profile `hello`: OTel env vars pointing at `lgtm:4318`, healthcheck on `/healthz`, `mem_limit`. **No port published**: it is reached only through Traefik.
- [ ] Makefile: `hello-up` starts Traefik and the hello services (and observability, which they need)

### 4. Traefik with tracing (45 min)

- [ ] `traefik:v3.7.13` in Compose (released 2026-09-21; v3.7.14 is under two weeks old), profile `hello`
- [ ] Entrypoint `web` on `127.0.0.1:8080`. The Traefik dashboard, if enabled, also only on `127.0.0.1`.
- [ ] File provider: route `PathPrefix(/fastapi)` → strip the prefix → `http://hello-fastapi:8000`
- [ ] Traefik's built-in OpenTelemetry tracing → `lgtm:4318`, service name `traefik`
- [ ] Traefik passes the W3C `traceparent` header to the service, so the service's spans join Traefik's trace instead of starting a new one. **This header is what turns two traces into one.**
- [ ] `mem_limit`, healthcheck (`traefik healthcheck` with its ping endpoint)
