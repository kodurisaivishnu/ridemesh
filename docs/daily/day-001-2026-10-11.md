## Problems and learnings

- The plan assumes 16 GB RAM; this laptop has 7.4 GB. Fine for today. On Day 2, run observability in the low-memory way: the `grafana/otel-lgtm` single container or Grafana Cloud free.
- A GitHub token was pasted into the AI chat, which makes it leaked: chat transcripts are stored and sent to the model. Fix: revoke it and make a new fine-grained token for this repo only. Prevention: secrets are typed only into the terminal prompt, never into chat, code or URLs. A pre-commit hook now blocks GitHub tokens from being committed.
- `docker` failed: *Cannot connect to the Docker daemon*. Cause: the CLI context points at Docker Desktop, which was not running. The native Docker Engine was running all along. Fix: the Makefile exports `DOCKER_CONTEXT=default` for this project only. The native engine has no VM, which matters with 7.4 GB of RAM.
- Postgres 18 images store data in `/var/lib/postgresql/18/docker`, so the volume mounts `/var/lib/postgresql`. The old `/var/lib/postgresql/data` path is wrong for 18.
- A Postgres healthcheck over the socket can report "ready" during first-start init. Checking over TCP (`-h 127.0.0.1`) waits until the init scripts finish.
- Kafka advertised listeners: clients connect to whatever address the broker advertises, so containers and the laptop each need their own listener.
- Conda `base` activates in every new terminal. Run `conda deactivate` before `source .venv/bin/activate`, or use `uv run <command>`, which always uses `.venv`. To stop the auto-activation for good: `conda config --set auto_activate_base false`.

## Decisions

- Python 3.13 instead of the plan's 3.12: already installed, and the planned libraries support it.
- No changes to system or global config for this project: everything goes in the repo (`git config --local`, project files).
- Push over HTTPS with a fine-grained GitHub token, stored only in this repo's `.git/credentials`. No `gh`.
- Postgres 18 (plan said 16): native `uuidv7()` for the capstone, and the local `psql` client is 18.
- Two roles per service (`_owner` for migrations, `_app` for runtime): least privilege, so the app cannot drop or alter tables.
- Redis `noeviction`: a full Redis must fail loudly, not silently drop driver locks.
- Native Docker Engine for this project (`DOCKER_CONTEXT=default` in the Makefile), not Docker Desktop.
- One shared dev password for all service roles locally; each role gets its own Secret in Kubernetes (Phase 5).
- Three frameworks or two: decide before Day 3, when the first hello service is written.
